# GABA 인덱스 운영 프로토콜

## 실행 순서

모든 고도화 작업은 다음 순서를 따른다.

1. **Intake** — 요청을 원문 그대로 기록하고 목표와 관련성을 확인한다.
2. **Normalize** — 결과, 완료 조건, 범위, 가정, 위험, 중단 조건을 정리한다.
3. **Compose** — 필요한 역할만 선택하고 실행자와 독립 검증자를 분리한다.
4. **Plan** — 산출물, 의존성, 검증 방법이 있는 작업 단위로 나눈다.
5. **Execute** — 독립 작업은 병렬로 진행하고 외부 권한 오류는 반복하지 않는다.
6. **Verify** — 데이터 정확성, 출처, 문구 안전성, 공개 범위를 점검한다.
7. **Act** — 검증된 변경만 커밋·배포하고, 위험한 외부 행동은 승인을 요청한다.
8. **Observe** — 사이트 응답, 검색·필터 상호작용, 데이터 품질을 확인한다.
9. **Adapt** — 오류의 원인이 데이터·지침·도구·완료 기준 중 무엇인지 구분해 수정한다.
10. **Close or Continue** — 완료 조건을 충족하면 종료하고, 부족하면 다음 작업을 만든다.

## 작업 분해 규칙

작업은 정보 이득, 병렬성, 위험 감소가 조정 비용과 지연 비용보다 클 때만 분해한다. 한 번의 책임 단위로 수행 가능하고 완료를 관찰할 수 있는 작업은 원자 작업으로 유지한다.

## 근거 레코드 검증 게이트

레코드를 공개 인덱스에 포함하거나 승격하기 전 다음을 확인한다.

- GABA 직접 섭취 또는 규제 문서의 성분 식별이 확인되는가
- 경구 경로, 제형, 용량, 기간, 대상이 확인되는가
- 대조군과 주요 결과가 확인되는가
- 안전성 정보와 자료 제한이 분리되어 있는가
- DOI·PMID·공식 원문 등 검증 가능한 연결이 있는가
- 연구의 의미와 마케팅 활용 방안이 결과를 과장하지 않는가
- 철회·정정·중복 상태가 반영되었는가

확인하지 못한 항목은 추정으로 채우지 않고 `확인 필요`, `부분`, `보류` 등 상태로 남긴다.

## 의사결정 기록

서로 다른 자료가 충돌하거나 공개 문구의 위험이 있는 경우, 대화 대신 다음 항목을 남긴다.

```yaml
question: 무엇을 결정하는가
alternatives: 선택 가능한 처리
criteria: 판단 기준
evidence: 사용한 출처와 레코드
assumptions: 확인되지 않은 가정
dissent: 반대 의견 또는 불확실성
recommendation: 권고안
decision_owner: 결정 책임자
expiry: 재검토 시점
resulting_actions: 후속 작업
```

## 배포 게이트

배포 전 데이터 검증, 중복 ID·DOI·PMID 검사, 문구 안전성 검사, 검색·필터 동작 확인을 통과해야 한다. 공개 릴리스에는 내부 토큰, 개인 식별정보, 내부 저장소 연결정보를 포함하지 않는다.
